# PGx Watch

An evidence-led pharmacogenetics surveillance agent for your **Anima simulation world**, with a separate AI GP reviewer and a lightweight review interface.

## Run

Requires Node 22.13 or later. The existing `api.json` is read only by the backend; it is ignored by Git. Its keys are `OPEN_AI` and `simulator`. Environment variables override them; see `.env.example` (export these variables in your shell, or use Node's `--env-file` option).

```sh
npm install
npm --prefix frontend install
npm run dev
```

Open **http://localhost:3000**. The backend listens on **127.0.0.1:3100**. On a machine with an older Node version, use `npx --yes --package=node@22 -c 'npm run dev'`. Use the same Node 22 runtime for installation and checks.

Use **Run review** to scan PGx correspondence, the 15-patient sample, one patient, or the full directory. Review-only mode still runs both agents and stores GP decisions. Enable **Execute GP-accepted actions** to apply accepted plans to the simulator. A finding can also be executed or re-reviewed individually. The Activity tab contains scan failures, decisions and simulator receipts; the Rules tab contains the full policy; Automation configures event polling and scheduled runs.

```sh
npm run scan -- sample                 # Evidence + AI GP review, no writes
npm run scan -- documents --execute    # All PGx discharge correspondence + accepted writes
npm run scan -- all                    # Full directory, GP and hospital records
npm test
npm run typecheck
npm --prefix frontend run build
```

Full scans are intentionally explicit and can take substantial time for the 50,000-patient world. They page through every patient, retrieve both scopes, and avoid model calls where no interpreted PGx evidence is available. Each completed page persists a cursor; interrupted full scans can resume from Activity. Correspondence scans are the fast path for the supplied sample. **A correspondence scan is not labelled a complete population scan.**

## What is implemented

- Anima ADK `0.6.0`, OpenAI provider, schema-defined evidence and GP agents.
- Deterministic rule matching after extraction; sample patient IDs are test-cohort hints, never the matching criterion.
- Primary document evidence; citations are resolved from source fields, rather than generated by a model.
- Separate GP acceptance, denial and deferral with persisted ADK sessions and concise rationales.
- Real simulator task, referral, consultation and persistent PGx problem-alert writes.
- Revalidation immediately before execution, durable outbox, simulator idempotency keys and per-workflow locks.
- SQLite scan history, decisions, event deduplication and audit trail.
- Manual API/CLI, authenticated event ingestion, 30-second simulator polling, and interval scheduling.
- Real React review interface; no fabricated patient rows or success counters.

## What the sample does not authorize

These rules largely request **specialist prescribing review**. Accepted findings create tasks/referrals naming the appropriate specialist; the GP agent does not invent a replacement medicine, dose or appointment slot. The simulator exposes `draft_prescription`, review/accept transitions and appointment booking, but this sample does not supply an executable prescribing or booking protocol. Those operations are deliberately absent from the execution allowlist. A referral receipt means a referral was created, not that the specialist changed treatment.

Abacavir avoidance creates a persistent **PGx problem alert**, not a fabricated allergy. DPYD starting-dose guidance is carried into an oncology referral, never used to halve a current dose. Family and pending controls create appropriate follow-up tasks. Normal and negative controls create a consultation record. WRITE TEST documents are excluded; the rest of that patient's evidence is still evaluated. Unphased SNP fixtures are preserved as contextual records, not converted to complete diplotypes.

## Policy files

`rules/pgx.json` contains the twelve rules and original guideline links. Edit structured rules and restart the service. New rules must also have an explicit matcher and permitted action implementation; arbitrary prose is not silently promoted into executable policy. The next rules text can be reviewed and added through the same process. `docs/architecture.md` explains the design, API discoveries, tradeoffs and extension points.

## Automation and operation

Automation is off until enabled in the interface. It runs while the backend process is alive; this is not an installed OS service. For cron, invoke `npm run scan -- documents --execute` from this directory under Node 22. Choose review-only by omitting `--execute`. The shared SQLite lock prevents concurrent CLI/server scans.

The event feed exposes only 100 recent events. Event polling therefore cannot guarantee complete delivery. A missing overlap triggers a correspondence reconciliation; schedule full scans if you need population-wide reconciliation, including changes outside correspondence. `POST /api/events` accepts `{ "id": "unique-event-id", "patientId": "SIM-000051" }`, deduplicates successful events and processes the patient's current state. It does not automatically register a webhook in the simulator.

Data persists in `data/watch.sqlite` and ADK sessions in `data/agents.sqlite`. Preserve both across restarts. No simulator key or OpenAI key is sent to the browser. The server binds to loopback. Set `APP_TOKEN` before any reverse proxy or remote deployment, and enforce authenticated access at that proxy. Hosted frontend deployments require server-side `BACKEND_URL` and `APP_TOKEN` and an always-on reachable backend; a frontend deployment alone cannot host the agents or SQLite database.

## Verification and limits

Tests cover patient/relative separation, pending/normal/negative controls, unknown diplotypes, evidence grounding, action allowlists, paginated scope reads, durable request identity on uncertain writes, and a scripted ADK structured-output run. Live validation results are recorded in `docs/validation.md`.

Clinical extraction and review remain probabilistic. This is a working simulator prototype, not a validated clinical prescribing system. A stale snapshot blocks new execution; multi-action plans can partially complete, and the outbox retains every completed step and original request ID for reconciliation. Simulator writes are not a cross-resource transaction. Future policy changes need evaluated clinical test cases and versioned action migrations.
